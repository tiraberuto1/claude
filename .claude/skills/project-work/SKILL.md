# 標準の作業手順

依頼内容: $ARGUMENTS

依頼内容が空なら、何をするのかを利用者に一度だけ尋ねて止まる。

## 1. 資料を確認する

- 対象のフォルダと、そこにある `README.md`・`SPEC.md` を読む。
- `tasks/active.md` を読み、進行中の作業とつながるかを確かめる。
- 次の 3 つを短く書き出す: 対象、完成条件、変更しない範囲。分からないものは「未確認」と書く。

## 2. 必要なときだけ計画を立てる

- 1〜2 ファイルの軽い修正なら計画は省き、3 へ進む。
- 3 ファイル以上を変える、生成物を作り直す、仕様に関わる場合は、手順を 3〜7 行で示す。
- AGENTS.md の「変更の境界」に当たる操作を含むなら、実行する前にその操作の承認を得る。

## 3. 小さく実行する

- 一度に変えるのは一つの論点だけにする。依頼にない整理や改善はしない。
- 生成スクリプトを実行する前に、上書きされるファイルを伝える。

## 4. 検査する

- `docs/ai/checks.md` から、該当する合格条件と検査コマンドを選んで実行する。
- 結果を「成功」「失敗」「未実行（理由）」に分けて記録する。

## 5. 修正する

- 失敗したら原因を一つに絞って直し、4 に戻る。
- 次のどちらかに当たったら止まる。原因、試したこと、足りない情報を `tasks/handoff.md` に書き、利用者に報告する。
  - 同じ失敗が 2 回続いた
  - 修正と検査の繰り返しが 3 回に達した
- この上限は、このプロジェクトの運用で決めたもので、Claude Code の仕様ではない。

## 6. 引き継ぐ

- `tasks/active.md` の「状態」と「検証の証拠」を更新する。
- 次の作業者に必要な事項を `tasks/handoff.md` に書く。
- 利用者には、変更したファイル、検査結果、未確認の事項、次の一手を短く報告する。
- 公開・送信・購入・commit・push は、この手順に含まれない。
