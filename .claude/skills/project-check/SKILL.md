# 合格条件での検査

対象: $ARGUMENTS（空なら、現在の未コミットの差分全体）

この手順では検査と報告だけをする。ファイルは直さない。直すかどうかは利用者が決める。

## 1. 範囲を決める

- `git status --short` と `git diff --stat` で、変わったファイルを一覧にする。
- 対象が指定されていれば、その範囲に絞る。

## 2. 合格条件を選ぶ

- `docs/ai/checks.md` から、対象に当てはまる節を選ぶ。共通の節は必ず含める。
- 当てはまる節がなければ、その旨を報告し、共通の節だけで検査する。

## 3. 検査する

- 「実行」と書かれたコマンドだけを実行する。それ以外のコマンドを思いついても、合格条件として扱わない。
- 「手動」の項目は自分で確認できる範囲だけを確かめる。画面の操作が要るものは「未実行（利用者の確認が必要）」とする。
- 必要なら Subagent `project-reviewer` に、合格条件、差分、元の資料を渡して、別の視点で読んでもらう。テストの実行結果は自分で取って渡す。起動できなかったら、自分で観点を変えて確認し、「独立レビュー未実施」と書く。

## 4. 報告する

次の形で報告する。

```text
対象: …
結果: 合格 / 不合格 / 判定保留
| 合格条件 | 結果（成功・失敗・未実行） | 証拠（コマンドの出力や該当行） |
未確認の事項: …
依頼外の変更: あり（ファイル名）/ なし
```

合格条件を勝手に緩めない。証拠がない項目は成功にしない。
