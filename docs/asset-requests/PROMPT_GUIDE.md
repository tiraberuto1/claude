# 画像発注のプロンプトの作り方（手引き）

出典: ユーザーが共有した「画像生成の指示書の作り方」（2026-10-10）を、このプロジェクト向けに整理した。
発注プロンプトを作る・直すときは、この手引きと `TEMPLATE.md` を使う。実際に効いた・効かなかった経験は `docs/PROGRESS.md` §5。

## 1. 基本の考え方
**主役しか書かないと、それ以外は全部 AI のおまかせになる。** 9 つの欄をすべて埋める。

| 欄 | このプロジェクトでの書き方 |
|---|---|
| 用途 | ゲームのどこで使う素材か（例: 主人公の攻撃アニメーションの 1 コマ） |
| サイズ | 大きさ・縦横・形式・背景（例: 1536×1536 の透過 PNG） |
| 主役 | 人物の装備・色・素材・特徴まで言葉で書く（基準画像を添付せず、言葉で指定する） |
| 動き | 姿勢・動作を、体の部位ごとに具体的に（脚・腕・刀・視線） |
| 構図 | 向き（体と顔をそろえた斜め左）、人物の大きさ（高さの約 70%）、足の高さ、余白 6% 以上 |
| 光と質感 | 平らな岩絵具の塗り。陰影・光沢・グラデーション・ひび割れ状の質感なし |
| スタイル | 実在する酒呑童子絵巻の大和絵。現代的なアニメ・漫画・RPG の絵にしない |
| 文字 | 画像内に文字は入れない（入れる場合は「」で囲み、位置・回数を指定） |
| 禁止 | 指定以外の文字・ロゴ・署名・枠・説明図・効果・背景・影・他の人物 |

## 2. 参考画像は「どこを借りるか」まで言い切る
「この画像みたいに」と書くと、背景や人物まで丸ごとコピーされる。添付ごとに、借りるところと借りないところを書く。
- 例: 添付1＝線・塗り・色づかいの参考 / 添付2＝顔・体つき・向きの参考。絵巻の背景・建物・他の人物はコピーしない。
- 基準の MASTER 画像は、そのまま写されるので**添付しない**（#003 v1 の失敗）。

## 3. 直すときは「1 か所だけ」＋「変えないもの」
- 直したい点を 1 つに絞り、「〇〇だけを〇〇に変える。次は変えない: 顔立ち・髪型・装備・衣装の色と文様・太刀・構図・画風」と書く（#001 v2・#003 v2 の修正依頼がこの形）。
- 一度に何か所も直すと、何が効いたか分からなくなる。

## 4. 当たりの画像を土台にする
- 気に入った 1 枚を添付し、変える所だけ言葉で指定すると安定する。ただし、**姿勢が変わる発注では、添付した絵のポーズまで写される**ので、姿勢を変えたいときは使わない。人物の同一性がずれたときの 2 回目の手段として使う。

## 5. 納品後の採点は 1 つだけ
- 検収（Claude Code が実ファイルを計測し、目視する）では、**一番大きな問題を 1 つ選んで直す**。同時に複数を直させない。
- 必要なら ChatGPT に画像を見せ、「主役・構図・光と質感・文字・禁止事項の 5 点でチェックし、一番大きな問題を 1 つだけ選んで、直す指示を 1 文で」と頼むのも使える。

## 6. 一言からプロンプトを作らせる（人が使う場合）
ChatGPT に次を貼ると、足りない項目を質問してくれる。
```
これから作りたい画像を一言で伝えます。それを画像生成用の詳しいプロンプトに書き直してください。
用途、サイズ、主役、動き、構図、光と質感、スタイル、入れる文字、禁止事項の9項目で書くこと。
情報が足りない項目があれば、書き直す前に質問してください。
作りたい画像：〇〇
```

## 7. 仕上げ
- 細かい文字や数字が入る画像は画質設定を「高」にする（このプロジェクトでは文字は入れない）。
- 納品後は、サイズ・透過・余白・向き・装備を 1 つずつ確認する（数値で計測する）。

## 8. このプロジェクトに当てはまらない部分
図解・グラフ・表・スライド（文字や数字が入る画像）の項目は、ゲーム素材の発注では使わない。
