# ゲーム仕様（草案）

状態: 草案。未確定の項目は `【要確認】` と書く。
基準: 白紙化した `CLAUDE_CODE_RESTART_SPEC.md` の内容（git 履歴 `98f14ba` 以前）を要約した。原本の文言とずれる場合は原本側を優先する。

## 1. 概要

- 題材: 実在する「酒呑童子絵巻」
- ジャンル: 2D アクション（横スクロール）
- 体験: 絵巻そのものが動き出し、絵巻の世界を操作しているような体験
- 進行方向: 右から左（都から大江山へ向かう）
- エンジン: Godot 4.4.1（GL Compatibility）。`godot/project.godot` を Godot で開いて実行

## 2. 世界観と画風の基準

- 絵巻の大和絵としての造形を維持する
- 絵巻の平面的な構図、筆線、岩絵具を思わせる色彩、雲、余白、人物の簡略化を尊重する
- 現代的なアニメ・漫画・RPG・一般的な和風ゲームの表現に置き換えない
- キャラクターを過剰に格好よく、美形に、筋肉質に描かない
- 3D 的な陰影・光沢・派手なエフェクトを避ける
- キャラクターだけが背景から浮いて見えないようにする

最終判断基準: 「このキャラクターを基準となる酒呑童子絵巻の画面に置いたとき、もともと絵巻に描かれていた人物のように見えるか」。見えなければ修正する。

## 3. 資料の優先順位

| 優先 | 資料 | 役割 |
|---|---|---|
| 1 | サントリー本《酒伝童子絵巻》（https://www.suntory.co.jp/sma/collection/data/detail?id=626） | 全体の基準（画風・色彩・構図・人物・衣装・甲冑・武器・雲・余白） |
| 2 | 東京国立博物館《酒呑童子絵巻》（孝信本）（https://www.tnm.jp/modules/r_exhibition/index.php?controller=item&id=8231） | 源頼光・四天王など武者表現の補足 |
| 3 | 《土蜘蛛草紙絵巻》（https://emuseum.nich.go.jp/detail?content_base_id=100257&content_part_id=000&content_pict_id=000） | 古い武者の顔・身体の簡略化・姿勢・衣装・武器の補足 |

3 つの画風を混ぜて平均化しない。第 1 を基準にし、残りは必要な箇所だけ参照する。

## 4. 登場人物

- 主人公: 源頼光
- 敵・人物: 酒呑童子、四天王（渡辺綱・坂田金時・碓井貞光・卜部季武）、鬼 【要確認: 敵の種類と数】
- 造形の基準: 頼光の MASTER CHARACTER を最初に確定し、以後のモーションはすべてそれに従う

## 5. 操作（案）

【要確認】 以下は前回の試作（Phaser 版）の操作を引き継いだ案。Godot 版での入力割り当てを決める。

- 歩く: ← → / A D（左が大江山）
- 奥・手前: ↑ ↓ / W S
- 跳ぶ: Z / Space
- 斬る: X / J（空中で斬ると跳び斬り）

## 6. 攻撃・当たり判定（方針）

- 攻撃は 1 種類を基本とし、空中攻撃は跳び斬り
- 攻撃判定は攻撃モーションの特定フレームでのみ有効にする
- 攻撃の順序（ATTACK）: 元の 6 フレーム案ではフレーム 3 と 4 が逆だった。修正意図は「1 → 2 → 4 → 3 → 5 → 6」。刃は基本的に下向き。柄・鍔・刃・鞘を混同しない
- 【要確認】 攻撃判定の数値（開始・終了フレーム、リーチ、ダメージ）

## 7. 体力・被弾・死亡

- 頼光の体力: 5 【要確認】
- 被弾（HIT）: 2〜4 フレーム。攻撃と混同せず、死亡状態へ移行させない
- 死亡（DEATH）: 3〜6 フレーム。被弾後に力を失い崩れ落ちる。フレームの欠落や番号の重複を認めない
- 【要確認】 無敵時間、ノックバック

## 8. 進行と構成

1. 都を発つ（出立）
2. 橋（記録点 A）
3. 大木（記録点 B）
4. 大江山の大鬼（記録点 C）・ボス戦
5. 館の門へ（クリア） 【要確認: 段数と各段の敵配置】

- 道中の「記録の場」で頼光の姿を保存し、一巻の絵として残す 【要確認: 記録の仕組みを残すか】
- 背景だけが横に動く一般的なゲームで終わらせない。異時同図などの絵巻特有の表現を、将来的にゲームの仕組みとして取り込める構造にする

## 9. 画面と演出

- 画面は斜投影（絵巻の平行投影）を基本とする 【要確認: 横視点か斜投影か】
- 絵巻の詞書（縦書きの文章）を表示する演出 【要確認: 採用の有無】
- 画面全体の色彩・サイズ・接地を、基準となる絵巻の画面に合わせる

## 10. 素材（制作ルール）

- 画像（キャラクター・背景・モーション・スプライトシート）は Claude Code が独断で作らない。発注プロンプトを作り、ChatGPT が制作する（`docs/asset-requests/`）
- API キーは使わない
- 画像の使用フロー: 発注 → 納品 → 検証（透過・サイズ・フレーム順・視認性）→ 組み込み → 動作確認
- 画像の生成だけで実装完了と判断しない

### 10.1 MASTER CHARACTER（最初の工程）
- 全身の基本立ちポーズ、背景透過、顔・髪・衣装・甲冑・武器の一貫性
- 基本造形が承認されるまで、別のキャラクターや大量のモーションを発注しない

### 10.2 モーション（目安）
| 動作 | 目安フレーム | 注意 |
|---|---|---|
| IDLE | 2〜4 | わずかな動き。呼吸や揺れを誇張しない |
| WALK | 4〜6 | 右から左。頭と胴の向きを一致させる。ループで跳ねない |
| ATTACK | 3〜6 | 上記 6 の順序と刃の向き |
| HIT | 2〜4 | ATTACK と混同しない |
| DEATH | 3〜6 | フレーム欠落・番号重複なし |

## 11. 完成の定義

絵巻の造形を守ったキャラクターが、統一された素材仕様で動き、絵巻の画面そのものがゲームとして機能すること。
画像が大量に生成されることは完成基準ではない。
